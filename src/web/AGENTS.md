# Web interface

`app.tsx` owns routing and the inspector layout. `components/sidebar.tsx` owns sidebar interactions, modifier hints and shortcuts; `lib/navigation.ts` owns their mapping. `pages` owns views, `components` owns shared controls, and `styles.css` owns the palette/layout. Use `lib/api.ts` for HTTP and `../shared/contracts.ts` for wire types. The browser must not import server, runtime, ports, or provider code.

`theme.css` owns the semantic light/dark colors used by shared controls, pages and modals. Dark primary controls use pale lavender with dark text; outline controls use distinct control fill, border, text and hover tokens. Pink remains the navigation accent. Keep content images, PDFs and browser frames unchanged. `public/theme-init.js` selects the saved `sidekick.theme` value or OS preference synchronously in the document head before app rendering. `lib/theme.ts` handles accepted changes, cross-tab updates and OS changes when no explicit choice exists. Storage failures must leave the current session usable. `lib/ui-preferences.ts` also contains best-effort sidebar, Inspector visibility and width preferences; denied reads or writes must never prevent navigation or rendering. The sidebar and mobile top-right navigation menu expose the same labelled switch; standalone secure forms and `/browser` inherit it without fetching app state. Browser and touch icons are real local assets under `public`, declared in `index.html`; preserve `/favicon.ico` as an image response.

The sidebar contains Chat, Goals, Schedule, Apps, Channels, and Vault. `pages/goals.tsx` and `pages/schedule.tsx` show saved plans. Creation and changes dispatch `sidekick:compose` with `{text,send:false}` through `lib/secondary-pages.ts`; the app opens chat and the composer keeps the prompt as a reviewable draft. Each row also provides Delete through `components/delete-plan.tsx`, with one local confirmation. Delete calls the owned API, removes only the accepted record from the page cache, fences stale reads, and preserves schedule execution history. Personal context and setup are conversational; there is no separate profile page. Vault login links open dedicated secure forms; verification-code requests and action confirmations stay in chat. Message inspection dispatches `sidekick:inspect-message`; the app focuses the internal run without adding tasks to the user chat. The inspector is resizable and opens beside chat without forcing the sidebar to collapse; at intermediate widths, it stacks below the main view when the sidebar is expanded; `/dev` opens it directly.

Cmd on Mac or Ctrl elsewhere plus J/G/S/E/D/K opens Chat/Goals/Schedule/Apps/Channels/Vault only outside editable fields. Inspector and sidebar collapse have no shortcuts; B and I remain available to the editor and browser. Direct Inspector and Get started sidebar controls appear only in development. Production uses the More menu for Inspector and Restart setup, with a visible explanation that setup starts a new chat and keeps saved data. Respect the server Inspector setting in both builds. Hold the modifier for 650 ms before showing letter hints, outside icons on the collapsed rail; ordinary shortcut taps must not flash hints. Editable fields suppress all page shortcuts and hints, including nested contenteditable and shadow inputs. Preserve labels, current-page state, arrow/Home/End navigation and focus return. At widths of 640 px or less, a compact top bar exposes Chat and a top-right Navigation menu. Put the other page links, theme switch, Inspector and Restart setup inside that menu; remove bottom navigation and hide collapse controls. Preserve native modified link actions, current-page labels, Escape/outside dismissal and focus return. Close the menu after navigation or a desktop resize. Account for top and bottom safe areas without covering the composer. Narrow Inspector fills the workspace and closes when a page is opened. Secondary pages share header icons and an empty-state baseline. Goals and Schedule use the same tab height and section gap; direct empty states reserve that same controls area so Vault aligns without a fake tab. Apps uses the larger PlugZap icon and an outline Connect or Add account action on each service; reserve pink for selected navigation and primary actions on other pages.

`lib/composer-editor.ts` owns Tiptap extensions and input handling. Enter sends; Shift+Enter adds a list item inside bullet, numbered and task lists, lifts an empty item out one level, and adds a newline elsewhere. Preserve native formatting shortcuts, composition handling, Markdown round trips and file paste behavior. `composer.tsx` owns draft and upload state; sidebar shortcuts must never intercept editor keys.

Keep conversation central and quiet. Preserve working state, timestamps/date history, reactions, file/image attachments, and quoted replies. `pages/chat.css` keeps the available conversation width, adapts gutters to the chat container, and keeps message actions directly beside the content in a column sized to its controls, without covering text or changing layout on hover; narrow views use an options button in that column. User bubbles align right, with actions on their left and a compact timestamp inside the bubble; assistant timestamps stay below their replies. `components/chat-turn-rail.tsx` compresses loaded user turns into a bounded scrollable stack with one tab stop and arrow/Home/End navigation; highlight every turn section that intersects the conversation viewport; preserve the current keyboard target, previews and reduced-motion behavior. `components/message.tsx` renders Markdown with sanitized embedded HTML; keep URL checks and local-link handling in `lib/message-links.ts` and `lib/markdown.ts`. Do not allow raw unsanitized HTML or arbitrary remote image loading. `composer.tsx` handles pasted images and files; there is no microphone recording control. Read aloud and microphone controls are absent.

`components/emoji-picker.tsx` starts with six native quick reactions and More in an anchored, nonmodal popover. Only More lazy-loads the searchable category/skin-tone/flag catalog. Preserve arrow/Home/End navigation, outside-click/Escape dismissal and focus return. `components/emoji-picker.css` is imported by `main.tsx`, not the component, so Node fixtures can import the component. `shared/emoji.ts` validates reactions; `lib/reactions.ts` renders legacy aliases and toggles equivalent Unicode values. The same user emoji removes the reaction. Agent reactions remain distinct, render as small labelled noninteractive badges only on user messages, and never cause a wake loop. Do not render malformed emoji or assistant-target badges.

`components/attachment-images.tsx` owns the shared attachment gallery and modal viewer. Pending uploads show thumbnail-only previews; raster images, audio, video and PDFs share bounded tiles with at most four visible tiles and an overflow count. Keep viewer names and sizes visually hidden; show a counter and controls. Preserve owned artifact URLs, arrows/Home/End without moving focus, native media seeking, Escape, close and focus return. Unsupported files remain download tiles. `composer.tsx` keeps upload order, aborts removed/unmounted uploads and revokes temporary blob URLs without losing failed-send drafts. Import `components/attachment-images.css` from `main.tsx`, not the components.

`components/link-previews.tsx` reads sanitized rendered anchors and loads at most two eligible links per persisted message near the viewport; streaming text must not fetch previews. A message with a valid local credential link keeps its ordinary links but does not fetch or show cards, including for the website named beside that link. `lib/link-previews.ts` caches/deduplicates requests and accepts only opaque local image-proxy URLs. Reuse `shared/link-preview.ts` screening, escape metadata and retain normal links on failure. Vault, approval, login, consent and private destinations must not produce cards. Existing owned artifact rendering also handles published screenshot PNGs.

`hooks/use-app-state.ts` refreshes persisted state and `lib/streams.ts` handles deltas. Reconcile by stream ID, not task ID; stale refreshes must not erase a later message. Retain accepted stream text across an SSE reconnect until its persisted stream ID arrives. Render live and saved replies through the same message component and stream-based React key so persistence does not replace their DOM node. State refresh discards unfinished streams for failed or cancelled tasks while preserving completed-ID fences. Position an optimistic send before paint and preserve the existing history boundary; sending must not remount the conversation or composer. Owned unexpired verificationRequests from app state identify private code replies: mask their optimistic text immediately, target the exact request when unambiguous, and never retain a code in retry signatures or restored drafts. Use the accepted response messageText as canonical display text. Numbers without a matching pending verification request retain normal chat behavior. Every Get started entry dispatches `sidekick:restart-setup`; Chat performs one deduplicated reset and then onboarding with the returned `conversationRevision`. Do not reset on mount or while the model is unavailable. Fence state, history, submissions and deltas by revision, and remount the composer so old drafts/uploads cannot enter the new chat. Preserve accounts, Vault, saved personal context, goals, schedules and other channels. A failed reset leaves the existing conversation intact. `lib/schedules.ts` preserves wall-clock times and custom cron expressions.

Apps uses one aligned list of services, local logos, and verified account labels when available. Keep compact service, account and action columns on wide pages; move accounts below the service at narrow widths. Center each service logo against its title and description. Account names and email addresses wrap in full. Place a direct Disconnect action beside each account and omit connected checkmarks. Disable that action while its request is pending. Keep Connect and Add account aligned in the action column; account count must not create uneven neighboring cards. Keep all services visible with one Connect or Add account button per service; an unavailable service keeps its disabled action. Do not repeat identical account names and email addresses. `components/connection-menu.tsx` provides the mobile navigation menu with arrow/Home/End navigation, Escape, Tab, outside-click and focus dismissal, and focus return; do not replace it with a native select or details disclosure. `pages/apps.css` is imported by `main.tsx` after the shared secondary-page styles. Abort pending connection requests when leaving Apps and ignore late responses so they cannot redirect a different page. Scope disconnect actions to a connection ID, update the accepted cached result and fence older reads before refreshing. Automatic updates have no user toggle or notification setup copy in the account rows; the API retains actual pending/unavailable delivery state. Channels introduces unconfigured services before a small-step setup wizard. Ready rows show identity and useful delivery status. The primary Start conversation action opens the verified Telegram bot link without sending or opening a popup automatically. Remove channel is a direct quiet action with one confirmation; accepted removal returns focus to Connect. Finish setup opens saved delivery guidance in a dialog with Escape/Close focus return. There is no replacement setup menu or repeated requirements copy in the list. `pages/channels.css` is imported by `main.tsx` and adapts to the available page width. Send secrets only to its secure server endpoint after the final step, clear them on close/success, and never restore them from status responses. Preserve current configuration until verification succeeds. Saved configuration or a registered webhook does not prove message delivery.

`pages/secondary-pages.css` styles the secondary views with shared design tokens and full available page width; preserve common edge padding instead of adding a narrow centered column. Import it after the global stylesheet. `hooks/use-page-data.ts` uses the memory-only `lib/page-data-cache.ts` store to keep the last good view visible across navigation, refresh silently on mount/focus and revalidate active pages from the existing SSE refresh stream. Deduplicate reads, preserve cached data on failures and advance the request generation after accepted mutations so late responses cannot restore removed accounts. Show loading only before the first result and keep failures visible. Page headers have no manual refresh controls. Channels rechecks status on mount, focus and accepted setup changes.

Goals separates Active and Completed with keyboard-accessible tabs and cached counts. Paused goals stay in a separate disclosure under Active, expanded when there are no active goals. Keep each view’s empty state specific; no archived status exists. Goal cards expose named regions, labelled progress and goal-specific action labels. Keep progress, target date and next step when pausing or resuming. `pages/goals.css` owns the tab, paused disclosure and narrow-layout rules; import it from `main.tsx`. Goals and Schedule provide Try again only after a failed read and keep cached content usable during recovery.

Schedule separates Upcoming from read-only History using keyboard-accessible tabs and focusable panels. Display one-time dates and recurring cron timing in each schedule's IANA zone; do not coerce a one-time task into cron. Common cron intervals have readable labels; uneven intervals remain Custom timing. When no tasks are upcoming, expand the paused schedules so their Resume actions remain visible. History uses the global cursor endpoint so deleted schedules remain visible, merges runs by ID and uses actual task statuses. A successful execution says Finished; it does not establish that the user's objective was achieved. Creation, pause/resume and changes remain chat drafts. The first history page is cached across navigation; older cursor pages belong to the mounted history view.

Secure form values stay out of URLs, local storage, chat, and logs. Clear them after submission. Preserve expired/retry, staged login, and unsupported-method states. Sign-in and verification methods are chosen in chat; Vault forms collect only login identifiers and passwords. Trusted verification-code requests use chat and bypass normal message routing and plaintext persistence. Inspector refresh must pause during secure work and distinguish live, last-known, and unavailable images without hiding chat.

Vault uses one Add to Vault action for Login and Payment card. Login entries have a user-defined name and exact website origin, with several entries allowed per origin. Cards save a name, cardholder, number, expiry and optional three/four-digit CVC/CVV. The private UI list shows full login usernames and card brand, last four digits and expiry. Never put passwords, full card numbers, security codes or code-presence flags in list metadata, `usePageData`, shared caches or browser storage. Keep agent-facing `savedEntries` masked and login-only. The manual Website domain field accepts a bare domain; the broker normalizes it. Secure forms show the fixed observed origin and collect a name, identifier and password together on an identifier step, and require a name on a password step. Use another login reveals fresh fields. A rejected saved login opens the new secure form; preserve the nonsecret typed name while clearing credentials. Suggest an editable website-based Name and avoid repeating an existing same-website name. Preserve custom names through saved-login switching and retry. OTP forms never offer saved passwords or ask for a name.

Opening a saved Vault entry loads its details through a separate no-store POST. Password, card-number and security-code reads occur only after explicit Show or Copy; copying a hidden value does not reveal it. Keep the code-presence flag in the active details component only. Abort and fence reads on close, entry change and unmount; hiding or leaving the window clears revealed values. Clipboard errors use fixed text. Keep deletion out of list rows: the details modal contains Delete and an explicit confirmation with Keep as the initial focus. Preserve keyboard access and focus return, with Add to Vault as the fallback after a row is deleted. Row-name buttons use a subtle keyboard outline, without a pink ring, underline or filled row.

Vault details open directly as an editable form for Name and login or card fields, using the saved entry's PATCH route. Show Save changes and Cancel changes only while the form differs from the saved item or a secret change is open. Cancel changes restores saved nonsecret fields and clears replacement inputs. Keep a login's website fixed. Show the stored website identifier label when available, with Username as the fallback. Saved secrets stay masked; an explicit Change action opens a required empty replacement input. Cancel change clears it and restores focus to Change, leaving the existing secret unchanged. Security codes also support Add and Remove; send null only for an explicit removal, and omit unchanged values. Clear replacements on submit, cancel, close and window hiding. Fence late creates, edits and deletes after unmount or entry changes. Empty status text must not reserve footer space; feedback precedes the bottom actions. `components/vault-item-form.tsx` shares the add/edit fields and expiry parsing; `components/vault-details.tsx` owns detail, reveal, copy and confirmation states. Keep names, domains with ports, usernames and card metadata readable at narrow widths. `components/vault-details.css` owns these layouts.

The inspector has Screen, Activity, Tools, Models, Costs and Prompts. Diagnostics start owner-wide; inspecting a message narrows Activity, Tools, Models and Prompts until Show all. `components/inspector-work.tsx` shows current work grouped by outcome, queued follow-ups, saved upcoming schedule times and recent background decisions. Read these from the bounded `/api/inspector/work` response, not the latest task-history page. Show registered review timing without inventing a next heartbeat. Activity shows paired execution history directly below current work. Tab navigation uses roving tabindex and arrow/Home/End keys; narrow panels wrap into two rows of three labelled tabs. `components/inspector-tools.tsx` owns execution history, recent calls, grouped tool usage, the available-tool catalog and the separate Models view. Recent calls is the default Tools view; By tool retains per-tool pagination, while Available tools exposes descriptions with collapsible schemas. Models shows recorded requests, token categories and the separate assistant-model subtotal. `lib/inspector-observations.ts` owns paging/filtering. Render inputs, outputs, prompts, errors and schemas as escaped text. Keep the existing bounded pages and explicit older-page controls. Use full retained server counts, stable timestamp/ID cursors and direct attributed provider costs; missing prices stay unavailable.

`components/inspector-providers.tsx` owns the Costs tab. `lib/provider-usage.ts` groups each provider with visible operation/model summaries and expandable metrics and one owner-wide recorded-cost subtotal. Costs remains owner-wide during message inspection. Never add overlapping model/tool subtotals to this ledger total. Keep unknown prices distinct from zero and note the retained window and partial coverage. Do not show native dropdowns or a recording-coverage inventory. `components/inspector-prompts.tsx` reads the private prompt endpoint and shows snapshot metadata directly; only instruction text is collapsed. Never expose prompt snapshots in ordinary chat, local storage or public links.

`components/attachment-pdf.tsx` lazily loads PDF.js and its bundled local worker only when an owned or pending blob PDF opens. Render a bounded canvas page with separate page controls; preserve gallery navigation outside those controls and Escape to close. Abort stale loads, cancel rendering, destroy document workers on close/change and use a fixed retry/download fallback. Do not enable document scripting, XFA, remote worker/assets or weaken artifact CSP. Raw filenames stay outside visible viewer chrome.

Read [API contract](../../docs/api-contract.md) before changing requests. Reuse existing controls. Validate changed flows in the local app at desktop/narrow widths, including waiting/error states. Fixtures and configured labels do not prove live OAuth, login, or channel delivery.

`pages/inspector.css` owns inspector and browser-window layout. `hooks/use-inspector-state.ts` and `components/inspector-screen.tsx` are shared by the Inspector and the dedicated `/browser` page. Unknown/network failures keep recovery polling; neither path displays raw response messages or retains an unsafe frame.

Browser controls distinguish inline manual control from native sign-in. In `sign_in` mode, replace ordinary captures with the active lease’s transient workspace desktop frames from `hooks/use-sign-in-screen.ts`, enable bounded private input, and show Resume agent for active work or Done for finished/standalone control. Suspend ordinary capture during acquisition and native control; reset its capture guard and fetch a fresh frame after release even when task ID/activity did not change. Frame URLs and typed text clear on blur, hidden tabs, task/revision changes and unmount; abort pending reads and discard late bytes. Never put these frames in shared Inspector state, artifacts or storage. A missing private frame disables input while continuation and retry remain available. Keep asynchronous status reads fenced so old polls or a previous task cannot replace an accepted mode change. The container browser keeps the isolated task profile, not the user’s ordinary browsing session.

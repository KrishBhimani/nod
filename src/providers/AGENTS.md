# Provider adapters

Implement the smallest applicable interface in `../ports`. Factories accept credentials and configuration explicitly. `../server/composition.ts` chooses implementations. Provider SDKs, protocols, transport parsing and vendor defaults stay here.

| Provider                  | Capability                                                                      |
| ------------------------- | ------------------------------------------------------------------------------- |
| `pi`                      | OpenAI/Anthropic agent sessions, transcripts and stateless conversation routing |
| `agent-browser`           | Browser actions, HTTP(S) proxy, observations and credential injection           |
| `docker`                  | Workspace execution, files and normal Docker networking                         |
| `composio`                | Google/Slack/Notion authorization, tools, file retrieval and signed events      |
| `chat-sdk`                | Telegram/WhatsApp webhook protocols and message transport                       |
| `openai`                  | Speech and cheap event classification                                           |
| `jev`                     | Optional browser chooser and relevance classifier                               |
| `keychain`, `environment` | Vault encryption key source                                                     |

Adapters must not import feature modules or runtime implementations. Normalize errors and output shapes. Never expose keys, OAuth tokens, raw SDK sessions or plaintext vault contents to the runtime, model or web client. The key-store port returns key bytes only to trusted vault and channel-settings services. SDK state that must persist needs an explicit reference and migration policy.

`chat-sdk/settings.ts` verifies account details without changing provider state. Its separate registration method applies the exact encrypted configuration already persisted by channel settings. Telegram retries must reuse the saved webhook secret and retain pending updates; a lost response does not justify generating another secret or restoring unknown remote settings. Provider fixtures cover this sequence without real accounts or message delivery.

`openai/relevance.ts` uses the installed OpenAI model catalog without network discovery. Send `reasoning_effort: none` only when the selected model declares that off value. Non-reasoning models omit reasoning parameters; models with unknown capabilities omit optional reasoning and sampling fields. Keep the shared default in `shared/model-defaults.ts` and cover model overrides in `provider-adapters.test.ts`.

Before swapping an adapter, follow [replacing modules](../../docs/replacing-modules.md). Test its protocol mapping separately from product behavior. Browser work must retain exact-origin credential checks, observation locks, bounded output and cleanup. Workspace subprocesses must not inherit provider keys. Review [security](../../docs/security.md).

`pi` translates completed assistant message usage into the provider-neutral `model_usage` event, including turns that only call tools. Preserve separate cache token counts and label SDK costs as estimates. Never invent rates or count persisted history again. Include a distinct failed attempt only when the SDK reports usage for it. These events exclude separate compaction, cache-warming, speech and browser-provider charges. Keep deduplication and retry behavior covered by `pi-agent.test.ts`; these fixtures do not verify a provider bill.

`pi/conversation.ts` implements the conversation-routing callback through `ModelRuntime.completeSimple`. It uses the shared GPT-6 Luna or Claude Haiku 4.5 catalog default, an explicit model override when configured, server credentials, in-memory configuration, no tools, no session, no catalog refresh and no stored conversation history. Keep the input/output caps, shared five-second budget, zero retries and strict decision union. A continued outcome must match a supplied candidate. Candidate text and bounded recent conversation are untrusted data; routing never grants permission or bypasses waits and revisions. Preserve explicit null outcome provenance for ordinary conversation, omit task/message IDs, and bound the extra context to 12 messages of 1000 characters. The server owns fallback and routing policy. The optional usage callback records one `relevance/conversation_route` operation with only SDK-reported tokens/cost estimates; invalid responses still incurred an operation, and late reported usage after cancellation stays cancelled. Test these boundaries with `pi-conversation.test.ts`; no live provider call is required. The [earlier C22 probe](../../docs/testing/results/2026-09-25-c22-routing.md) records the previous routing investigation; a small successful probe is not an intent-recognition guarantee.

`agent-browser/login.ts` owns trusted login inspection and method selection scripts. Scope detection to an active visible dialog or focused form, clear prior markers, and deduplicate equivalent OAuth controls. Ambiguous fields or forms stay unsupported. `credentials.ts` owns typed secure entry. Support identifier, password and one-time-code stages using observed fields; never request those values through the model. Method selection must recheck the origin and current control. Passkeys, separate windows and split-digit secure-code entry remain unsupported.

Credential submission checks fresh visible rejection feedback for at most two seconds while observations remain locked. Only bounded status and fingerprints leave the feedback script, never error text or entered values. Distinguish a new error or replacement document from a stale alert, and require the credential stage to remain present. `submitted` means entry occurred, not successful authentication. `rejected` lets Vault rotate the one-use form without resuming or saving bad input. Keep delayed rejection, password/OTP correction, unchanged expiry and stale-token tests in `vault-rejected-login` and feedback visibility/freshness checks in `credential-feedback`.

`agent-browser/manual.ts` validates browser takeover input. `index.ts` reserves control before awaiting the per-session queue and blocks agent actions, credential injection, login inspection and method selection until release. Recheck locks inside queued work. Send typed text only through the private daemon socket, protect the focused editable field, and mask screenshots/observations. Release, close and the fixed 30-minute expiry invalidate pending input; expiry does not resume the task. Known protected fields remain blocked through alternate model selectors. Socket protocol mappings must match the pinned agent-browser version, including recovered-session click, fill, attribute and scroll commands. `hold` retains a waiting browser only to its bounded expiry. New launches are limited to four tracked live sessions per Computer. Capacity allocation is serialized and evicts the oldest idle, unheld session while retaining its profile and masked last-known frame. Queued or running operations, injection, manual control and native sign-in are protected; if every slot is protected or cleanup fails, a new launch fails without exceeding the limit. Recovery of pre-existing daemons and multiple worker namespaces are separate from this per-Computer launch bound. Cover capacity, close failures and concurrent reservations in `browser-capacity.test.ts`.

`agent-browser/screens.ts` stores masked screenshots and bounded metadata in private files. The optional `screenStatus` describes the preceding `screenshot` result as live, last-known or unavailable. Inspector recovery must not navigate, launch a browser or replay credentials. The socket recovery path is bound to agent-browser 0.38.1's protocol; keep its mapping tests when changing that dependency. A restarted credential-bearing session uses its cached image until an explicit reopen because secret redaction values stay in memory only.

Mark current browser activity when an accepted action starts, before awaiting navigation or browser commands. Long-running work must be discoverable by the inspector, and an older action finishing later must not override a newer accepted action. Preserve manual-control priority and rejection/cancellation checks before changing activity. The held-navigation fixture in `runtime-adapters` covers this ordering.

Known Chromium network navigation failures use the fixed `BrowserActionError` code. Persist only the validated destination without query or fragment and the failed state; never expose the raw CLI error. A failed page has no usable login form or current screenshot. Snapshot returns a bounded diagnosis with no controls, including after restart. An explicit new open closes the failed session before using a fresh proxy and clears the failure only after navigation succeeds. Keep HTTP(S)/userinfo validation and exact-origin secure-entry checks; cover this behavior in `browser-navigation.test.ts`.

Run the focused browser/vault checks with `npx tsx --test tests/browser-login.test.ts tests/browser-manual.test.ts tests/browser-recovery.test.ts tests/takeover.test.ts tests/runtime-credentials.test.ts tests/runtime-adapters.test.ts tests/vault-staged.test.ts tests/vault.test.ts`. The vault tests require `TEST_DATABASE_URL` for a disposable schema. The staged DOM/socket fixtures and isolated synthetic Chrome pages do not prove a live provider login works.

`chat-sdk` advertises Telegram attachment support and maps byte-backed PNG/JPEG/WebP images up to 10 MiB to photo uploads; other files use document uploads. It accepts no remote attachment URL or filesystem path. A logical delivery can use multiple provider requests; preserve an uncertain result after any partial failure. WhatsApp attachment delivery is not implemented. Test these mappings with `channel-artifacts.test.ts`; its fetch fixtures are not real recipient delivery.

`container-browser/config.ts` selects headed Chromium for ordinary workspace browsing. On Linux, `index.ts` starts a separate private Xvfb display for each launched task and passes only that display's environment to the browser CLI. Reuse the display while that browser lives; close it only after confirmed browser closure, including eviction, cancellation, native handoff and disposal. Failed browser closure keeps the display available for cleanup retry. `browser-headed` covers launch environment, task separation, handoff, interrupted launch and failed close. Headed automation still uses CDP and is not a claim that a provider accepts automated sign-in.

`agent-browser/sign-in.ts` opens the same container `/usr/bin/chromium` and private profile without automation or debugging flags. `desktop.ts` owns a private authenticated Xvfb display with no TCP listener, bounded in-memory screenshots and fixed xdotool input with text on stdin. Keep sanitized environments and bounded owned-child shutdown. Continue requires normal quit and confirmed process/display cleanup; forced cleanup cannot resume. `index.ts` blocks ordinary observations/input while sign-in is pending, while separate owner-only native methods serve transient frames and input. The automated display closes before native launch; continuation creates a fresh automated display. Persist the pending fence and restoration preference across restart, redact the return path and never reopen after cancellation or expiry. Version-resolution fixtures remain factory tests; production never falls back to host Chrome. Cover helpers in `browser-desktop`/`browser-sign-in` and adapter races in `browser-sign-in-handoff`; fixtures do not prove real provider acceptance.

`container-browser` implements the host Computer through a fixed Docker stdin bridge. Its persistent worker owns the existing browser adapter, proxy, profiles and screenshots inside a separate trusted browser container. `container-browser/config.ts` selects the fixed native Linux agent-browser binary for the container architecture, avoiding the npm launcher wrapper. Interrupted browser commands must close and drain that exact daemon session before cancellation completes; failed cleanup retains the task lock. Keep the private `/data/control.sock` at mode 0600, application namespaces derived from data-root hashes, strict method/input bounds and namespace-specific disposal. Never expose the socket, profile volume, desktop or CDP to the untrusted shell workspace, or fall back to a host browser. Credentials and input travel only over stdin; replies use bounded private frames and fixed public errors. Cancellation must reach the worker and await terminal acknowledgement before the host continues; missing acknowledgement fences further actions. Premature disconnect quarantines the worker namespace until pending work and Computer disposal finish, including when the host restarts. Explicit disposal drains only its namespace. Each namespace permits at most 32 pending calls; the worker accepts at most 256 connections. Cached activity and screen metadata cannot regress when older replies arrive. Native sign-in frames use separate owner-only methods and never enter the normal screenshot cache. `container-browser.test.ts` exercises the real Unix socket and bridge with synthetic Computers; it does not prove Docker, Chromium or a live provider. The worker's injectable factory supports isolated test scripts without a production environment switch or certificate override.

The workspace uses the normal Compose network with no Sidekick egress firewall or network-guard sidecar. Keep its unprivileged user, dropped capabilities, resource limits and restricted mounts. Network reachability follows Docker and host routing; do not claim LAN, metadata or IPv6 filtering. The acceptance harness obtains its one attached network from Docker inspect, validates the name and attachment, and reuses that network for its disposable workspace; it does not accept a user-supplied network or join a host/container namespace.

Workspace commands use `docker/command.ts`, a fixed Python supervisor started through Docker exec. Commands and file contents travel on stdin. The supervisor owns a process group, enforces the timeout/output limit and acknowledges completion or cancellation only after that group has stopped, including children left after their shell exits. The host waits for this acknowledgement; a lost connection or missing acknowledgement fences the adapter until restart and cancels and drains other pending commands. Disposal also aborts and drains pending commands. `docker/index.ts` reads publication and image-attachment bytes inside the container through `Workspace.readArtifact`: walk directory descriptors with `O_NOFOLLOW`, accept a regular file only, and bound its size and final read. Never resolve an untrusted workspace path into a host read. The workspace remains a single-owner shell environment, not isolation between arbitrary commands or task directories.

Login inspection chooses a focused candidate-containing form before inferring a generic identifier. Multiple unfocused forms remain ambiguous. Reject named, inherited or non-current browsing targets both when advertising a method and immediately before secure submission. Same-origin embedded manual fields use their actual focused document and retain field/text masking across at most sixteen documents; inaccessible frames use the native sign-in handoff instead of weakening protection. Ordinary cross-origin page content remains observable before secret entry; unreadable frames are hidden when a protected value has been collected. This is credential masking, not a prohibition on reading the user's authorized private page content. Browser recovery uses streaming UTF-8 decoding. Host browser activity belongs to accepted actions, not later screenshot polls; disposal cancels and drains bridges that have not yet reached the worker before disposing the namespace.

Telegram polling must clear failed offset initialization so a transient database error can recover on the next poll. Keychain creation is serialized within its adapter; a competing process winning creation is reread rather than replacing its key. Public preview images accept bounded static PNG, JPEG and WebP only. Reject PNG animation chunks, truncated chunks and trailing payloads; do not advertise GIF. Existing public URL and redirect checks remain separate from unrestricted workspace browser networking.

Shutdown must attempt and drain every owned session before reporting a cleanup failure. Pi abort failures must not skip session disposal. Failed disposal remains retryable. The browser keeps its private proxy available until all sessions close, so a failed close can be retried. Container host and worker cleanup retries retain the unavailable namespace fence until the prior Computer is fully disposed; a restarted host cannot bypass that fence. Cover these failure paths with `pi-agent`, `browser-headed` and `container-browser`.

The drag and upload fixes add native agent-browser actions to Otto's browser tool. Upload reads only a file in the current task workspace, sends at most 12 MB to the isolated browser, and keeps a private temporary copy until the browser session closes. Browser task B46 and holdout B56 used this path. An old saved profile failed after a browser service restart in one B45 rerun. Saved public profile restart reliability remains unconfirmed.

## Findings

Native select, checkbox, hover, history, and tab actions let Pi use the website controls. The first synthetic login showed that Vault rejected browser references; Vault now accepts them and fills through the trusted browser. The code step uses a secure Vault link. Pi's app list shows saved browser profiles without Vault login entries or stale pending profiles. Private profiles now restore their browser session after a service restart. The TinyMCE editor was read only on the public site. The private mailbox path from PR #53 has integration coverage, but no real mailbox was used in the live runs.

## Fixture checks

- [PR #52](https://github.com/n8n-io/otto/pull/52): The browser fixture covers nested CMD choices, a phone field that unlocks on focus, a PIN field, and changed field or origin rejection.

# PR 1 review and fixes

The review examined all 60 Cubic comments against PR 1 at `a0a9c8e1592d80661800de83bd1b8185ec871e07`, compared with `9759e2bac355964fa0aadc48651cd36da2444fc6`. Independent specification, standards, provider, server/runtime and web passes checked the findings against the requested behavior and repository guides. This is a review of the full change, not a claim that every line or workflow was exercised.

## Five intentional disagreements

| Finding                                 | Decision and rationale                                                                                                                                                                                                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Shared workspace access (`4106113580`)  | Retain the documented single-owner shared shell workspace. Task folders organize files; they are not separate tenant sandboxes. Browser profiles, provider keys and Vault keys remain outside it.                                                                                    |
| macOS bind-mount claim (`4106113583`)   | The claim that UID 501 universally prevents Docker Desktop writes was not reproduced and conflicts with recorded write acceptance. Docker Desktop sharing differs from native Linux mounts; Linux UID portability remains a separate question.                                       |
| Reversible plan autonomy (`4106113575`) | Keep direct goal create/update and schedule create/update/cancel in the current owned user segment. Reintroducing a command-phrase gate would restore the rejected UX. Ownership, revision, validation and idempotency remain; this is not a semantic or prompt-injection guarantee. |
| Private Inspector labels (`4106113775`) | Keep useful redacted task titles in the owner-only Inspector, which also intentionally exposes effective prompts. Documentation now states that titles may summarize the start of a request. Redaction does not anonymize arbitrary private content.                                 |
| Unused task dashboard (`4106113599`)    | Keep work in chat and Inspector instead of restoring an unused dashboard. Remove the unused component while preserving Schedule status helpers and chat Stop.                                                                                                                        |

## Evidence and limits

Focused tests cover the changed policies, request races, cancellation, failure recovery and persistence. PostgreSQL checks use disposable schemas; integration and messaging fixtures do not deliver external messages. Existing fixed findings were verified rather than reimplemented. The final combined test, build, CI and UI acceptance results belong in [Verification](../../verification.md).

The controlled Apps fixture returned three cached accounts in 0.40 ms while all provider responses remained pending. The frozen reproduction took 153 ms for three serial 50 ms provider delays. These synthetic measurements demonstrate removal of the serial wait, not live vendor latency.

An actual isolated Docker check cancelled a command with a TERM-resistant child, observed no delayed file write, executed subsequent work and tested bounded artifact reads and symlink rejection. See [Provider boundary evidence](2026-09-25-provider-boundaries.md). Stop covers the supervised process group, not a deliberately detached process that starts another session.

This review does not establish real Google/X authentication, OAuth consent, remote subscription behavior, Telegram/WhatsApp delivery or provider billing. Earlier recordings apply to their listed source versions; current acceptance links and aggregate results are maintained in Verification.

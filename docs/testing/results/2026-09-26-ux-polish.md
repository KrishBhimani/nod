# UI and browser-control review — 2026-09-26

This pass implements the compact-layout and Inspector feedback. UI checks used the real local app in light and dark themes. The acceptance harness used separate PostgreSQL schemas, a separate workspace/browser container pair, synthetic app/channel data and one real model request against a public website. No normal account was removed and no provider message was sent.

## Changes

- Goals, Schedule and Vault share empty-state spacing. Goals and Schedule also share tab geometry.
- Apps use compact rows with account details beside the service on wide screens and below it on narrow screens. Full account labels wrap instead of breaking the layout. Logos are vertically centered against the service title and description. Direct Disconnect actions sit beside each account; connected checkmarks are removed.
- Mobile navigation keeps Chat in a compact top bar and puts the other pages, theme, Inspector and Get started in a top-right menu. The bottom bar is removed. The menu closes after selection, outside click, Escape and desktop resize.
- Channels have a direct Remove channel action with confirmation. Manage, Replace setup and the Meta requirement subtitle are removed. Verified Telegram accounts show a primary Start conversation link. Pending callback setup remains available through Finish setup.
- Dark primary buttons use lavender with dark text; secondary controls use a distinct plum surface and readable borders. Pink remains the navigation accent. All 72 sampled text/surface pairs meet 4.5:1 contrast in the two themes.
- Inspector has Screen, Activity, Tools, Models, Costs and Prompts. Activity, recent calls, provider summaries and prompt metadata appear directly. Empty work sections are compact; raw payloads and long instruction bodies remain optional disclosures.
- Vault uses Name and Add to Vault. Secure forms suggest an editable website-based name, add a number for existing same-website names, and preserve custom names through saved-choice switching and retry.
- Browser actions share one compact row. Secure pauses show neither the screen-hidden notice nor a Retry view action; narrow panels use a labelled popup icon.
- Take control opens the workspace browser even without an existing task or usable screenshot. Active work pauses and drains. Finished work keeps its page/profile; Done restores masked viewing without restarting the agent. A standalone session creates no task and closes on Done.

A later real sign-in check found a separate browser boundary defect: ordinary UI screenshots continued while the task waited for credentials. This avoids ongoing background captures during the wait; it does not claim to prevent every browser capture stall. Native control and interruption fences remain intact.

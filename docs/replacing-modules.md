# Replacing a capability

`src/server/composition.ts` selects adapters and binds feature factories. The web client consumes HTTP types; server features and the runtime depend on capability interfaces. Provider choice is operator configuration at startup, not a user setting. Replacement tests can use the same routes and durable workers without vendor services.

These interfaces hide SDK and transport details, not migration costs. A new provider key does not migrate OAuth account IDs, browser profiles, or transcript formats. The setup verifier currently covers Telegram/WhatsApp and returns a validated server-only configuration map; another channel requires an explicit setup schema and policy.

`Computer.download` optionally captures a file from the task's authenticated browser. It returns bounded bytes and validated file metadata to trusted runtime code; it does not expose browser cookies, profile paths or a shell read handle. `RuntimeContext.publishBrowserFile` stores those bytes under the immutable owner and active task revision, then replies on the originating channel. Replacement computers must retain the 12 MiB transfer limit, cancellation/drain behavior and private browser boundary. The model receives only the published artifact reference.

## Add an adapter

1. Read the applicable port and focused tests. Put the implementation under `src/providers/<provider>/`; accept configuration and keys as factory arguments.
2. Map vendor data to the port. Preserve cancellation, bounded output, and fixed public errors. Do not return SDK objects, credentials, or unrestricted execution handles.
3. Select it in composition. Keep product policy, routes, and UI unchanged when behavior is equivalent.
4. Run feature tests with an injected fake and protocol tests with synthetic vendor responses. Then exercise the HTTP-to-worker replacement fixture.
5. Plan existing-data handling and perform only authorized, bounded live checks. Record unresolved vendor behavior.

The key store returns key bytes only to the trusted vault and channel-settings services. Keep the same key when replacing its source, or re-encrypt both datasets deliberately. Envelope encryption, key rotation, and cross-host recovery are not implemented by the port alone.

## Hosted and self-hosted choices

The Cloudflare adapter hosts the gateway and tenants in private containers; `providers/runtime-host/local.ts` hosts the same tenant entrypoint as private child processes on a trusted Node host. Both implement `RuntimeTransport`, while `server/runtime-host.ts` owns provisioning, signing, leases and runtime environment construction. A new host must confirm the old generation stopped before replacement, preserve account reservations after uncertain failures and never publish an actor listener. The local transport uses PostgreSQL private storage and assumes all host processes and administrators are trusted. It is not an operating-system sandbox against other programs running as the same user.

`server/tenants.ts` provisions opaque app/jobs schemas and a restricted login for each environment/user UUID. `server/account-store.ts` and Better Auth use the separate private authentication schema. PostgreSQL can run locally or with a compatible managed provider; use a dedicated database and a provisioning connection with the required role/schema privileges. The provisioner defaults to eight users. Increasing it requires matching process/container capacity and a database connection budget. Moving existing local-owner data into hosted UUID accounts requires an explicit migration; changing `OTTO_MODE` does not perform one.

`OTTO_MASTER_KEY` derives tenant SQL credentials, runtime signing keys and Vault keys with separate purposes and environment/user context. Preserve the master and identity mapping across a host move. A new master, environment name or user UUID changes the derived values and is not a rotation procedure. Keep development and production provider projects, keys and databases separate. [The environment example](../deployment/hosted.env.example), [development guide](development.md) and [Cloudflare runbook](../deployment/cloudflare/README.md) cover the supported launch paths.

Docker, E2B and Cloudflare share the browser/workspace ports. Default single-owner mode supports Docker. The selected hosted provider is `COMPUTER_PROVIDER=cloudflare`, available only to tenant processes. It starts separate owner-bound browser and workspace containers on first use through the fixed private `http://otto.computer` broker. Composition captures the positive runtime generation, and every broker request includes that generation and its role. The Worker resolves owner authority from its private runtime grant; an old process cannot adopt a replacement generation by reusing a container identity. The optional, deferred E2B path uses one `E2B_COMPUTER_TEMPLATE` and one owner sandbox for browser, files and commands in local or hosted mode. Its fixed Linux users and checked helpers have implementation/fixture coverage; live E2B acceptance remains required before selecting it.

The Cloudflare Node adapter composes the existing browser bridge and command supervisor. Its browser namespace is `sk-` plus the first 24 hex characters of the canonical owner UUID's SHA-256 digest. Browser profiles remain under their owner directory in `/data`; workspace files and installed CLI tools share the separate `/home/node/state` checkpoint root through fixed `/workspace` and `/home/node/.local` symlinks. The Worker owns startup, lease checks, idle checkpointing, restoration and confirmed shutdown. Both images are unprivileged and have no service credentials. Workspace command execution remains capped at 120 seconds; a separate bounded host grace accommodates startup, restore and checkpoint acknowledgement without extending command execution.

A replacement provider needs the Computer/Workspace protocol, durable conditional state updates, lease ownership before side effects, cancellation and bounded file transfer. Unknown create, pause, checkpoint or termination outcomes must remain fenced. Do not give the command sandbox browser profiles, provider keys or the database connection. Replacing a provider does not transfer its filesystem or authenticated browser sessions automatically. Preserve a recoverable checkpoint, verify compatibility and stop the old writer before switching; do not treat a process-kill acknowledgement as proof that its descendants drained safely.

Cloudflare adapter fixtures use injected HTTP or launchers with real local Unix sockets and Python supervisors. Separate isolated Linux amd64 image checks have validated file modes, internal symlinks, hashes and failure-safe restore, plus synthetic Chromium cookie/local-storage recovery after deleting the original container. Local Wrangler checks validate Container.exec and the controller boundary. These are local proofs; production storage, real Google sign-in and account-isolated production execution require their own acceptance checks. See the [Cloudflare runbook](../deployment/cloudflare/README.md) for current rollout status.

Private artifacts and Pi checkpoints use PostgreSQL in local hosted actors (`server/object-storage.ts`) and the HTTP/R2 broker in Cloudflare. Tenant HTTP requests carry the immutable process generation in `x-otto-generation`; the generic HTTP adapter leaves it optional for other local transports. The filesystem and S3 implementations under `providers/object-storage` are alternatives; S3 requires explicit composition wiring. Filesystem storage requires a durable private volume and manual stale-lock recovery after an interrupted writer. Preserve conditional writes and owner namespaces when replacing storage: copy both bytes and metadata, reconcile uncertain actions, and only switch after the old writer is stopped. An object version from one backend is not interchangeable with another backend's version. Conditional cleanup must fail safely when unsupported rather than remove a replacement object.

## Keep policy outside providers

The integration feature owns the five Google service IDs, read allowlist, account selection, approvals, and watch intent. The adapter implements consent, verified account identity, scoped execution, subscriptions, and signed event normalization. It must honor the explicit provider account supplied for each action.

Disconnect/revoke connections under the old provider before switching integration backends. Existing references remain provider-tagged; the replacement must not reuse them. Pending approvals keep their local account binding and must fail when that account is unavailable. OAuth consent normally needs repeating with the replacement provider. Encrypted vault/channel records are independent and must remain intact.

The channel feature owns sender access, durable inbox/outbox, reply windows, and task routing. A transport verifies original webhook bytes, normalizes messages, optionally polls, and sends replies. Polling must await inbox acceptance before acknowledging an update. Replacement drains active delivery, then applies the new account/sender binding. Adding public ingress requires narrow changes to local access policy or hosted gateway/webhook routing; an adapter cannot broaden HTTP access itself. Hosted verified account claims must remain exclusive across users, and actor claim/release requests must retain their active-lease checks.

Saved channel setup is decrypted only for the trusted transport factory. Metadata endpoints must not expose its configuration map. A failed provider verification leaves current settings active; a remote webhook mutation and database commit cannot be made atomic by this interface. Current Telegram setup requires the user's numeric sender ID. One-time deep-link pairing and a verified test-message challenge remain proposed flows, not capabilities supplied by this port.

The classifier chooses relevance, but the feature keeps quiet hours, quotas, source identity, and dispatch deduplication. Browser adapters preserve exact-origin credential checks, observation locks, public-web restrictions, and non-navigating screenshot recovery. Workspace replacements preserve the separation from the host, provider environment, and authenticated browser.

## Replace a feature or storage layer

Feature factories own routes and persistence. For example, replacing `createPersonalService` changes personal context and scheduling while its HTTP/runtime contracts stay explicit. A visible contract change also requires `src/shared/contracts.ts`, the affected page, and [API contract](api-contract.md) to change together.

PostgreSQL and pg-boss are deliberate infrastructure choices. Replacing them requires a data and execution migration; there is no generic repository layer pretending otherwise. Artifact bytes have a storage port, while artifact ownership and metadata remain in PostgreSQL. Multiple gateways or a different worker topology must preserve the single active generation and confirmed-stop rules, not just share a database URL.

`npm run check` enforces import directions. `application-adapters.test.ts` covers replacement agent, computer, workspace, integration, speech, and key services through HTTP and workers. `channel-application.test.ts` covers setup/transport replacement and channel continuation. Hosted fixtures additionally cover SQL privileges, signed ingress, runtime generations, account sessions, private objects and computer allocations. Run the adapter's focused tests and the Cloudflare package checks when that boundary changes. Provider protocol fixtures, local provider checks and production acceptance answer different questions; none substitutes for the others.

If E2B is explicitly selected in a future deployment, composition exposes idempotent `prepareComputer` and reversible computer `pause`/`resume` separately from terminal disposal. That adapter's preparation runs through the authenticated account route, and server-side onboarding completion cannot bypass it. Cloudflare has no preparation hook; its browser/workspace roles start lazily on their first operation. The E2B `computer` allocation role never adopts old `browser` or `workspace` rows. Preserve their resources and fences for explicit operator migration; supplying legacy template keys is an error. A provider replacement must retain ownership, resource identity, pending receipts and pause/termination evidence, and must not reuse Cloudflare checkpoints as E2B state automatically. Ordinary users never choose this provider in the product.

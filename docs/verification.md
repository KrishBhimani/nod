### Current container implementation

The trusted browser worker and Chromium run in the browser container, including native sign-in on a private authenticated Xvfb display. There is no host Chrome fallback, published browser port or shell mount of browser profiles/control sockets. The app’s core Browser page shows transient owner-only native frames and sends bounded private input; ordinary/model captures stay blocked during sign-in. The same task profile returns to automation only after explicit continuation and native process exit.

Workspace and browser traffic now use normal Docker networking without a Sidekick destination or port deny policy. The separate public link-preview fetcher retains its own private-destination checks. Workspace privilege, resource and mount limits remain; network reachability follows Docker and host routing. Local app Host/Origin checks, ownership/revision validation, exact-origin Vault matching and secret storage remain separate controls. The database bootstrap generates private credentials and rotates the local PostgreSQL role through stdin. The normal local stack was subsequently checked as described below.

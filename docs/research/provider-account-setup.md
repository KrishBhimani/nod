## Validation status

Real PostgreSQL fixtures use a separate disposable local service, schemas and roles. They prove role-level cross-user isolation and the real Better Auth persistence boundary. A separate live Neon development preflight also verified two restricted logins, isolated queues, private object-store migration and cross-user access denials in a temporary database, then removed its test resources. Two actual local tenant processes retained separate preferences across a graceful gateway restart without calling model or computer providers. These are synthetic-user checks, not completed Google login or live provider acceptance.

The live development Composio preflight used the real adapter, one fresh synthetic UUID and one session to request consent for all seven supported apps. Each result was an HTTPS Composio link with a pending account bound to the expected development auth configuration. No link was navigated and no user authorized an account; tools and events were not exercised. The private resource journal was written before cleanup. All seven test pending accounts and the session were removed, direct retrieval confirmed absence and the synthetic owner's final account inventory was empty. No permission errors occurred, and existing app accounts, keys and configurations were untouched by this check.

The Cloudflare package passed its type checks, all 20 adapter/deployment tests and both environment dry runs. Real local Wrangler runs also passed Worker/gateway health, two signed-in synthetic tenant containers, private local-R2 upload/download and cross-user denial, then removed their disposable resources. A live development model request passed through the actual Pi adapter with the configured default model and server key. Full-suite counts, later recovery corrections and the limits of each check are recorded in the [hosted acceptance record](../testing/results/2026-09-26-cloud-hosting.md). No live container rollout has occurred.

The initial Cloudflare configuration admits at most eight users and retains active runtimes for schedules and event processing. It is a bounded pilot with ongoing compute costs, not a scale-to-zero design. The account already has the confirmed Workers Paid plan; this work made no plan purchase or change. No production deployment has occurred, and no live Sidekick login, integration webhook, Telegram conversation or remote-computer task is yet verified.

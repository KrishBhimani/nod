# Sidekick

A personal assistant with chat, persistent tasks, a browser, a Linux workspace, private credentials, and optional Google, Slack, Notion and messaging integrations. Built with TypeScript, React, Pi, Fastify, and PostgreSQL.

Sidekick has two entry modes. The default local mode is a single-owner app bound to `127.0.0.1`; keep it private. Hosted mode adds Google login, account settings and one isolated runtime/database role per user. The Cloudflare adapter and CI/CD are implemented for an eight-user pilot; a passing fixture or dry run is not proof of a working production account or provider connection.

## Run locally

Install Node.js **24.21.0 or newer** and start Docker Desktop:

```sh
npm run dev
```

The launcher installs missing dependencies, creates `.env`, starts PostgreSQL, the Linux workspace and the browser container, then opens [localhost:4310](http://localhost:4310). The launcher also creates a random PostgreSQL password in `.env` at mode 0600 and updates the existing local role without recreating data. The first run builds and downloads container images. Chromium is installed inside the browser image; Sidekick does not install or launch Chrome on your Mac.

Add provider keys to the ignored `.env`, then restart. Keep keys out of chat, source files, and screenshots.

| Configuration                                 | Purpose                                                                          |
| --------------------------------------------- | -------------------------------------------------------------------------------- |
| `LLM_PROVIDER=openai`, `OPENAI_API_KEY`       | OpenAI conversation and tools; also enables speech and fallback relevance checks |
| `LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` | Anthropic conversation and tools                                                 |
| `LLM_MODEL`                                   | Optional model override from the installed Pi catalog                            |
| `COMPOSIO_API_KEY`                            | Optional Google, Slack and Notion Apps consent and tools                         |
| `COMPOSIO_WEBHOOK_SECRET`                     | Signed connected-app event forwarding                                            |
| `TYPESAFE_API_KEY`                            | Optional Jev browser choices and relevance checks                                |
| `DATABASE_URL`, `PORT`                        | Server database and port; the launcher generates local database credentials      |
| `DEV_INSPECTOR=false`                         | Disable the inspector and new debug recordings                                   |

macOS Keychain supplies the encryption key for the vault and saved channel settings. Other hosts require `SIDEKICK_VAULT_KEY`; see [vault setup](docs/vault.md). Telegram and WhatsApp credentials can be saved through **Channels**, outside chat. Telegram supports local polling without a tunnel; WhatsApp still requires Meta callback setup and an eligibility check.

Ctrl-C stops the app. `docker compose stop` stops containers without deleting data. PostgreSQL, installed CLI tools and browser state use the `postgres-data`, `workspace-tools` and `browser-data` volumes. Task files, artifacts and transcripts use `.local/`. Deleting these loses local state. Existing host browser profiles are not copied into the container.

## Run the hosted pilot

Start with [deployment/hosted.env.example](deployment/hosted.env.example), copying it to the private ignored `.env.hosted.local` file and filling its required keys. The example selects `COMPUTER_PROVIDER=e2b` with one combined `E2B_COMPUTER_TEMPLATE`. Run `npm ci`, then `node scripts/start-hosted.mjs --check` and `node scripts/start-hosted.mjs`. This starts a Google-authenticated Node gateway and isolated tenant child processes at [localhost:4330](http://localhost:4330), using a separate development PostgreSQL database and real development E2B computers. No Cloudflare deployment is required. The [development guide](docs/development.md) also covers the optional local Wrangler/Cloudflare-computer path and webhook forwarding. The ordinary `npm run dev` launcher remains the single-owner Docker setup.

Hosted mode requires a dedicated PostgreSQL database whose gateway role can provision tenant roles/schemas, Google OAuth credentials, a stable 32-byte base64 `SIDEKICK_MASTER_KEY`, a separate `BETTER_AUTH_SECRET` and the chosen model key. Each tenant receives derived credentials and its own SQL namespace. The selected E2B provider requires a server-held `E2B_API_KEY` and one combined `E2B_COMPUTER_TEMPLATE`; browser actions, files and shell commands use the same owner sandbox. Legacy split-template settings are rejected and existing allocations require explicit migration. The local process host uses PostgreSQL for private files/checkpoints; Cloudflare uses its private R2 broker. Keep development and production databases, Google/Composio projects and keys separate.

Google sign-in uses `/api/auth/callback/google` on the configured `SIDEKICK_PUBLIC_URL`. Sessions determine data ownership; user-supplied IDs do not select another runtime. `SIDEKICK_DEVELOPER_IDS` grants computer/Inspector access to explicit account UUIDs; hosted diagnostic capture also requires `DEV_INSPECTOR=true`. Ordinary hosted users do not record Inspector prompts or tool payloads. Server startup selects models, computer provider and integration configuration; users only connect their own accounts. Hosted actors support Cloudflare or E2B; local single-owner mode supports Docker or E2B.

The default limit is eight provisioned users. The selected production shape is [Cloudflare Worker + private Node gateway/tenant containers](deployment/cloudflare/README.md), Neon PostgreSQL, private R2 artifacts/transcripts and one E2B computer per user. Authenticated onboarding prepares that computer before completion; a failure remains retryable without undoing Google sign-in. Browser and shell use separate Linux users inside that sandbox, with a checked private-control boundary. Ordinary users see chat and settings, not a computer/provider picker. Jan's existing Cloudflare plan still incurs its normal server/storage usage charges. The optional Cloudflare computer adapter and its earlier acceptance evidence remain available.

[CI](.github/workflows/ci.yml) runs checks, PostgreSQL fixtures, the client/container build and Cloudflare validation. [Production deployment](.github/workflows/deploy.yml) follows successful CI on the current `main` SHA and uses the GitHub `production` environment. Configure its secrets and public URL using the [deployment runbook](deployment/cloudflare/README.md). That workflow is repository code, not evidence that GitHub secrets, a cloud account or live integrations have been configured. Read [production limits and acceptance checks](docs/production.md) before sending a signup link.

## Use the app

The sidebar contains **Chat, Goals, Schedule, Apps, Channels, and Vault**, plus the account menu with profile, settings, theme and sign-out. Hosted accounts use their Google avatar. Cmd/Ctrl plus comma opens Settings. Other shortcuts outside editable fields use Cmd on Mac or Ctrl elsewhere: J Chat, G Goals, S Schedule, E Apps, D Channels, K Vault and B sidebar/menu. I toggles Inspector only for developer accounts. Hold the modifier for 650 ms to show navigation hints; arrow keys, Home and End also navigate the sidebar. The collapse/open control stays available. Mobile prioritizes chat with a menu for navigation and account settings.

Google signup opens a short app-connection onboarding screen. Computer preparation runs alongside app connections, and Continue waits until it is ready. Connect starts the app authorization flow directly; returning restores the same screen with its current connection status. Onboarding uses one compact connection state per app. The existing Apps page keeps its account management controls. Hosted users can access Chat, Goals, Schedule, Apps, Channels, Vault and account settings. Computer and Inspector views require developer access.

- One chat supports streamed replies, quoted replies, uploads, pasted images, artifacts, Unicode emoji reactions, grouped timestamps and history. Six common reactions open beside the message; More loads the searchable emoji picker. Selecting the same reaction removes it. Tiptap renders Markdown while editing, with no toolbar or preview switch. Typing `- ` starts a bullet list, including after Shift+Enter. Enter sends; Shift-Enter creates the next list item, exits an empty item, or inserts a line elsewhere. A slim rail jumps to loaded user turns. Eligible public links can show cached metadata and proxied image cards as messages approach the viewport; secure or unavailable links remain ordinary links. Markdown and embedded HTML are sanitized; there are no recording or Read aloud controls.
- Images, audio, video and PDFs use the same attachment viewer before and after sending. Galleries show up to four tiles with an overflow count. Viewer controls show a counter without filename or size metadata; arrow keys change the item without moving focus. Supported media use native controls, while unsupported files remain downloads.
- **Get started** archives the current web conversation, cancels its pending work and starts setup in a fresh generation. It preserves accounts, Vault, saved preferences, profile/memory, goals, schedules and other channels. Archived messages remain stored; no restore button or permanent deletion is implemented in this flow. This in-app conversation reset has fixture coverage only; the completed operator environment reset is recorded separately above.
- Live typing shows ongoing work. Longer requests get a concrete agent update when useful; elapsed time alone never inserts a canned reply.
- Each task has a separate browser profile. Developer accounts can open `/browser` to follow computer activity even when the optional Inspector panel is closed. Hosted ordinary accounts cannot access the computer view or its API. Normal captures are masked; secure steps pause observation and hide the browser image.
- The inspector has **Screen, Activity, Tools, Models, Costs and Prompts**. Activity shows current work and execution history. Tools opens recent calls, with separate grouped usage and available-tool views; Models shows request and token details. Message inspection narrows diagnostics. Costs keeps owner-wide provider and operation summaries visible; tool cost covers only directly attributed provider operations. Unknown prices stay unavailable. Private prompt snapshots show effective instructions and context for an execution, with redaction and seven-day retention. Only raw payloads, schemas, metrics and instruction text require expansion. These are recorded estimates and usage, not a provider invoice.
- **Take control** is available in the developer browser view. It opens the private workspace browser, including when no task has started. Active work pauses; **Resume agent** returns control after a normal browser shutdown. Finished work keeps its existing page and profile; **Done** releases control without restarting the task. With no browser session, **Done** closes the standalone browser. Click the browser image to type, paste, use shortcuts and scroll directly; Shift-Escape returns focus to the controls. Private control frames never become model screenshots or saved artifacts. Website acceptance is not guaranteed.
- Secure forms collect the selected website identifier and password together. Verification codes can be supplied directly in chat, including codes for unambiguous groups of four to eight single-digit inputs. The trusted server replaces the code with a masked receipt before history or model processing. For email codes, it first attempts a narrow lookup in the exact matching connected Gmail account; missing, ambiguous or unverifiable mail falls back to chat. Passwords still use the private form. Successful entry does not prove the website accepted the login.
- **Vault** has one Add to Vault action for logins and payment cards. Its list shows login names, websites and full usernames, or card names, brands, last four digits and expiry. Entries open directly as editable forms, with Save changes shown after an edit and confirmed deletion inside the modal. Saved passwords, card numbers and optional CVC/CVV stay masked; Show or Copy retrieves them only when requested. Change opens an empty replacement field. Copying a hidden value keeps it hidden, and closing the view or leaving the window clears revealed values.
- Explicit personal facts can be remembered from the current user's own quoted message. Profile learning requires an explicit statement or a matching answer. Known ordinary actions execute from a clear request; destructive or unclear actions ask for a specific confirmation in chat. Draft-only requests never authorize sending.
- **Goals** separates Active and Completed, with paused goals grouped under Active. **Schedule** separates Upcoming and History for one-off and recurring work. Create, update, pause and resume controls prepare chat drafts; the agent can apply validated local plan changes without a second confirmation. Delete uses one confirmation on the page. Saved data stays visible during background reads, with Try again after a failed read. Preferences, active goals, recent context and feedback inform inexpensive hourly reviews before a main-agent task starts.
- **Apps** supports multiple accounts for Gmail, Calendar, Drive, Sheets, Docs, Slack and Notion. Connected apps and More apps use separate card grids. Unconnected cards keep Connect beside the app name and description; connected cards have Add account in the header. Each account shows its full email or name with a × button to open a confirmation before disconnecting. Tools, confirmations, disconnect and watches bind to a specific account. Gmail/Calendar watches are requested by default; the API retains pending/unavailable delivery state without notification setup copy in the rows. A configured account is not proof of event delivery.
- **Channels** supports one allowlisted sender per user's Telegram or WhatsApp setup. Hosted Telegram bot identities are claimed across accounts so another user cannot attach the same bot. Connected and available channels use full-width rows, with the service on the left, Connect on the right and a × beside a saved identity to confirm removal. Telegram keeps Start conversation; incomplete setup keeps Finish setup. Telegram can upload owned task images/files; WhatsApp retains text replies and a web-app attachment fallback. Secure credential forms stay in the authenticated app; action confirmations use the originating chat. Media delivery fixtures do not establish live recipient delivery.

The Linux workspace can install CLI tools with `npm install -g` or `pipx install`. Node, Python, git, curl, and ffmpeg are included. In local Docker mode, browser and shell traffic use normal Docker networking without a Sidekick private-address, port or IPv6 deny policy; reachability follows Docker and host routing. The selected hosted E2B path uses one owner sandbox with separate browser/workspace Linux users; the optional Cloudflare path uses separate owner/role containers. Computers receive no service keys; command workspaces have no host Docker socket or authenticated browser profiles. Cloudflare checkpoints persist files, installed tools and browser profile data, not a running page's DOM or unfinished action; uncertain work stays quarantined for reconciliation.

In local Docker mode, the trusted browser has a separate container and private data volume, with no published port. The server uses a fixed Docker-exec bridge; the shell cannot access its profile, control socket or display. The sign-in view controls only that browser, not your Mac or a general desktop. Task directories and installed tools share one local-owner workspace; they are not tenant isolation. Network access can transmit workspace content or reach other accessible services, so these controls do not prevent every prompt-injection or data-disclosure attack.

## Quiet work and current limits

Hourly reviews need Jev or an OpenAI relevance key, including when Anthropic runs the main agent. Default notification rules favor time-sensitive requests, meaningful calendar changes, and concrete goal progress. Quiet hours block automatic task starts; an hourly review can still save a decision for later. At most two automatic event/review tasks start per hour. Background work suppresses streamed prose and automatic final replies, with explicit messages reserved for useful results or necessary questions. There is no guaranteed digest delivery.

Schedules, polling and reviews require the selected runtime to stay available: the local app and Mac, or the hosted pilot's active gateway/tenant containers. Interrupted external actions need review before retry. WhatsApp sends only within the accepted sender's 24-hour reply window; templates and delayed proactive messages are not implemented. Vault stores encrypted website logins and payment cards with explicit secret reveal. Passkeys, hardware-key interaction and card autofill are not implemented. Developer browser takeover pauses agent work through a revision-bound lease. Synthetic container/private-control fixtures do not establish live website login or 2FA acceptance.
